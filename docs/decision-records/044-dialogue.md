# 044: Dialogue

## Context

Inciting event (2026-11-04): breaking down the first slice, "The call and the lock-in" (issue #142), which needs the first parts of the dialogue infrastructure (issue #128): a text box at 320x240, lines in order, and fake choices. Later slices need branching, conditions on the game state, flags set from choices, and a "Sleep" option for every robot.

Goals and requirements (Neil):
- Not our own dialogue system.
- Good support for translation. The game's text is drawn at 320x240, where scripts differ a lot in how many pixels they need: Latin letters can be 8 or 9 pixels tall, Chinese characters at least 16.
- Using it may need coding. Every prospective collaborator codes, or wants to learn.

## 1. The backend

- [x] 1.1 Candidates: Ink, through GodotInk; Yarn Spinner; Dialogue Manager; and Clyde (Neil added the last two). Decision (Neil): Ink is ruled out on translation, which is not part of its model.
- [~] 1.2 What a desk spike found (Claude, 2026-11-04), from the projects' docs, not yet tried:
  - **Yarn Spinner**, the official C# integration for Godot. Lines get IDs, and its tools write CSV string tables, which become Godot `.translation` files read through `Tr()`. Its docs name Godot 4.1 and newer, and recommend 4.5; 4.7 is unconfirmed. A GDScript version is in alpha.
  - **Dialogue Manager**, an addon in GDScript with first-class .NET support. It uses Godot's own translation: static line IDs, `[ID:...]`, extraction through Godot's "Extract Translatable Strings", and CSV or PO. Its releases name Godot 4.7, and it is actively maintained.
  - **Clyde**, an addon in GDScript only, so C# reaches it through Godot's dynamic calls. Translation is a stated requirement of every feature, with tools to export lines for translators. Minimum Godot 4.3; the repository was last updated in August 2025, so its maintenance is in doubt.
- [x] 1.3 Decision (Neil): Dialogue Manager, provisionally, with no hands-on spike: we find out what it costs us while implementing. What to watch for, which a spike would have checked:
  - It builds and runs, and passes CI's checks: no files changed by the build, and none Godot writes left uncommitted.
  - A C# API that is typed, or can be wrapped thinly.
  - We can drive it: ask for the next line when our dialogue mode is ready for it, on our clock, rather than it running itself on Godot's timers or signals.
  - Translation through Godot's `TranslationServer`, with stable line IDs.
  - Its presentation can be ours: our text box, our font, and the garble (§3).
- [~] 1.4 What installing it found (Claude, 2026-11-05, issue #164), with v4.2.0, the latest, vendored whole into `game/addons/`, its editor plugin and its autoload on:
  - It builds, and the tests pass, but only once the project has been imported in full: gdUnit4Net imports a project it finds unimported by running the editor for 100 frames, and with Dialogue Manager's editor plugin that ends before the import does, so the scripts' classes are missing and the tile's mesh isn't imported. `scripts/dev-setup.ps1` now runs `--import`. On a fresh project, the plugin reports two errors as it imports, an unrecognized UID and a resource saved to an empty path, which change nothing.
  - Its C# API is a typed wrapper over the GDScript singleton: static methods and events, with `DialogueLine` and `DialogueResponse` as plain C# classes. Thin enough to use directly.
  - We drive it: we ask for each line, and nothing runs on its own timers. But it answers on Godot's frames, a frame or more after it is asked, with a .NET `Task`, so it can't be called from the tick. The text box, which only draws and runs on frames, calls it while the world is paused, and only the end of a dialogue reaches the tick (§2.4).
  - Its presentation is ours: we use none of its balloons.
  - Translation, tried in a copy with the debug dialogue, IDs written by hand and a French `.po` file (Claude, 2026-11-05). By default, a line's static ID, `[ID:...]`, is its translation key, in the context `dialogue`; a line without one is keyed by its text. Lines and responses came out in French through Godot's `TranslationServer`, with `--language fr`, from a `.po` file listed in the project's translations. Its editor plugin adds each dialogue file to the project's translation templates, `locale/translations_pot_files` in `project.godot`, for Godot's "Extract Translatable Strings", so a new file changes `project.godot` once the editor or an import sees it. The plugin's extraction runs headless only inside the editor (`--headless --editor -s` with a script); it gives each key and context, and a comment with the speaker and the English line, for translators.
  - Once any translation is loaded, every locale looks lines up by ID, English included: with no English translation, English shows the IDs, and a line missing from a locale's file shows its ID too (§5.3).
  - Speaker names are extracted for translation, but it doesn't translate them when it shows a line: the box has to, with `Tr(character, "dialogue")`.
- [x] 1.5 Its `DialogueLabel` for the text box (Claude, 2026-11-05, issue #165), rather than a plain label, which shows its inline tags as raw text and silently skips its inline mutations. Our subclass sets the settings its scene has, since its class alone is a plain `RichTextLabel` that asks for no height in a container, and garbles the line in `UpdateText`, which the label calls before typing it out. The label doesn't read input: jump skips the typing while it types, and goes on only after. Its C# version indexes its parsed text as a .NET string, in UTF-16 code units, where Godot's visible characters count codepoints, so a character outside the Basic Multilingual Plane shifts its punctuation pauses and splits a surrogate pair in its `Spoke` signal (§3.5).

## 2. The game while dialogue plays

- [x] 2.1 Dialogue pauses the game (Neil). A new mode in `GameModeManager`, like phasing: the menu and the map can be opened from it, and closing them goes back to it.
- [x] 2.2 Dialogue that plays without pausing, such as a rocket's "Yeehaw!" or a human's remarks, is a callout: a separate feature, for when one is needed. What would cancel a dialogue in progress is why it waits (Neil).
- [x] 2.3 The Voice has no avatar, or a big question mark as a placeholder (Neil).
  - Decision (Neil, 2026-11-06): the question mark, as a placeholder. Avatars are 48 by 48 pixels, over 32, 24 or 16: room for a detailed portrait, at the cost of a box taller than three lines of text. The player gets one too, which Neil drew, in a light border on a dark background, and is named `B-CON` in the dialogue files (Neil, 2026-11-06). The box finds a speaker's avatar by the name the dialogue files give it, from a directory of PNGs, so a speaker gets one by having an image, with nothing to list in code (Claude).
- [~] 2.4 How the game finishes the task of a dialogue from off the tick, which `046 §1.4` left to the dialogue interface (Claude, for Neil's review). Built: `ITick.NewCompletion()` returns a `TickCompletion`, whose `Task` the scheduler makes, and whose `Finish` and `Fail` the game calls when the dialogue ends, as with .NET's `TaskCompletionSource`. Finishing it only queues what waits. The alternative, a loop that awaits `NextTick` until a flag is set, needs nothing new in `Tasks` but has to be written at every such edge.
- [~] 2.5 Requests that come while a dialogue plays (Claude, for Neil's review). The game's presenter queues them, and `GameModeManager` starts each in turn while it stays in the dialogue mode, so that two dialogues asked for in one tick, such as by a `Fanout`, play one after the other, each finishing its own task.
- [~] 2.6 Dialogue asked for while slowing for a phase (Claude, for Neil's review): the game pauses for it at once, and the slowdown starts again from full speed when it ends, if the phase is still being aimed. Routing runs only on played ticks, so it can't be asked for while phasing.

## 3. Garbled text

- [x] 3.1 The Voice's broken lines are garbled when they are shown, not as written (Claude, agreed by Neil). Each trigger, or line, says how garbled; the text box replaces that fraction of the glyphs, from a seed taken from the line's ID, so a line garbles the same way every time. Writers and translators write the clean line. They lose control over exactly what shows, which matters little as long as the last of the call is clear (Neil).
- [x] 3.2 The garble can be animated, to draw attention to it (Neil).
  - Decision (Neil, 2026-11-06): the garble shifts. Every half second, which glyphs are garbled changes, from the line's seed and a step that counts the shifts since it was shown, and the fraction garbled stays the same. Over options: (a) the same glyphs garbled, each flickering to its letter now and then, which reveals the line more slowly; (b) the tofu jittering by a pixel or flickering in brightness, which hides the same letters for good. Shifting lets a patient player piece the whole line together, as the story's player pieces together the Voice's request, and the line still shifts the same way every time it is shown. The label sets its text again at each step, keeping how much of it has typed out; the garble replaces glyphs one for one, so its indices still hold (Claude).
- [x] 3.3 The garbled glyph is a box, "tofu", from a fallback font of one glyph at a codepoint in the Private Use Area, so that it looks the same whatever the locale's font (Claude, agreed by Neil). Tofu is not a codepoint but whatever a font draws for one it lacks, and Godot draws its own missing glyph with the hex code inside, and may fall back to a system font first.
- [x] 3.4 Only letters and digits are garbled (Neil, 2026-11-05). Spaces stay, so lines wrap as written, and punctuation stays, so the typing still pauses where it is written. Garbling every glyph but spaces would drop the pauses wherever punctuation was garbled.
- [x] 3.5 The tofu's codepoint is U+EB00 (Claude, 2026-11-05). Fusion Pixel draws glyphs of its own in the Private Use Area, U+E000 to U+E24F among them, so a fallback at U+E000 was never reached. Supplementary Private Use Area-A, U+F0000, which it leaves empty, was tried and rejected: one codepoint there is two UTF-16 code units, which Dialogue Manager's C# label miscounts (§1.5). A test checks that the dialogue font has no glyph at the tofu's codepoint, since any locale's font might.
- [x] 3.6 The tofu font is a PNG imported by Godot as an image font, so that an artist can redraw it, rather than a font built in code (Neil, 2026-11-05). Godot places an image font's glyph with the cell's middle on the baseline, whatever ascent it is given, so the box goes in the top half of a cell the font's line high.
- [x] 3.7 Each line says how garbled it is, with a tag, `[#garble=0.75]`, and the `Dialogue` entity no longer does (Neil, 2026-11-06). Garbling by the entity's fraction garbled every line of the dialogue, the player's too. Options: (a) writers tag the broken lines, which Dialogue Manager supports and takes out of the text, so translators don't see them; (b) garble every speaker but the player; (c) garble only the Voice. Both (b) and (c) single out a speaker by a name that is translated, and (b) garbles any third speaker in the scene. Decision: (a), with the fraction in the tag rather than on the entity, which leaves nothing to keep in step between the map and the file. The first slice's `Plea1` and `Plea2` were set to 0.75 and 0.25 in LDtk, for their lines' tags once `TheCall` is written.

## 4. Fonts

- [~] 4.1 Fonts with good coverage at 320x240. Pixel fonts exist for CJK at 10 to 16 pixels, such as Ark Pixel, and Unifont covers the Basic Multilingual Plane at 16. Licences and quality to be checked.
  - Decision for Latin (Neil, 2026-11-05): Fusion Pixel, 10 pixels, proportional, under the SIL Open Font License, over Ark Pixel, Monogram and m5x7: its family also covers Greek, Cyrillic, kana, Hangul and CJK. Its Latin version alone, as WOFF2, is 544 KB, so it is in Git, not LFS, like the other assets the game loads. At 10 pixels, its ascent is 11 and its descent 3, a line of 14 pixels, and a capital is 5 by 7 with an advance of 6. Fonts for other locales are still open.
- [~] 4.2 The text box lays out lines from the font's metrics, never in fixed pixels, so that a locale's font sets its line height (Claude, agreed by Neil). How many lines a box holds in each locale is open.
- [~] 4.3 Where a locale's font comes from (Claude, 2026-11-05, for Neil's review): the font, with the tofu font as its fallback, and its size are a theme's default, which a locale with a font of its own remaps with Godot's resource remaps. Not yet tried with a second locale.

## 5. Dialogue files

- [x] 5.1 Dialogue files are organized by story beat, not by level (Neil, Claude): a beat outlives the levels it spans, and maps to a slice, which gives translators a file's context. Lines shared everywhere, such as the "Sleep" option, go in a common file that others import. A long-running character may get a file of its own.
- [~] 5.2 A `Dialogue` entity in LDtk names its file and title as strings. The reader checks, when the world loads, that the file exists and holds the title, and a test that loads every world makes a wrong name a failure in CI. Enums in LDtk would have to be kept in step with the files by hand.
- [ ] 5.3 Translation keys (§1.4). Options:
  - (a) Static IDs as keys, Dialogue Manager's default, with an English translation file made from the dialogue files, so that English shows text. Editing an English line keeps its key, so translations stay attached, but nothing flags them as out of date.
  - (b) English text as keys, with the ID as context, by turning off its setting `use_static_ids_as_translation_keys`. English needs no file, and a missing translation shows English. Editing an English line changes its key, so its translations are lost until a translator's tool, such as gettext's merge, matches them up again, marked fuzzy for review.
  Either way, a test could check that every line has an ID and that every locale's file has every key.
- [x] 5.4 Fake choices, as in the first slice, where the player agrees to the Voice's request whatever they answer, are writing: responses whose branches meet again, which Dialogue Manager already does, with nothing in the box for them (Neil, 2026-11-06).
